HTML5 Exercises

Exercise 1: HTML5 Base Template

Objective: Ensure semantic structure and browser compatibility

What you'll learn:

  • <!DOCTYPE html> - Declares HTML5 document type (mandatory)
  • <html lang="en"> - Language attribute for accessibility
  • <meta charset="UTF-8"> - Character encoding for international characters
  • <meta name="viewport"> - Responsive design settings

Interview tip: "DOCTYPE html is required for HTML5 validation. The lang attribute helps screen readers, and viewport meta tag ensures mobile responsiveness."

Exercise 2: Navigation & Semantic Linking

Objective: Provide intuitive navigation using semantic HTML5

Key Components:

  • <nav> - Semantic container for navigation links
  • <a href="#events"> - Anchor tags with hash links
  • <section id="events"> - Matching ID for anchor navigation
  • <a href="help.html" target="_blank"> - Opens in new tab

Interview tip: "Using semantic <nav> helps search engines understand site structure. Hash links (#) enable smooth page navigation without full reload."

Exercise 3: ID vs Class Selectors

Objective: Differentiate between ID and Class selectors

Key Differences:

Feature ID (#) Class (.)
Uniqueness Unique per page Can be reused
Specificity Higher (100) Lower (10)
Usage #welcomeBanner .highlight

Interview tip: "ID is for unique elements and has higher CSS specificity. Classes are for styling multiple elements with the same style. CSS specificity: ID (100) > Class (10) > Element (1)"

Exercise 4: Tables & Image Gallery

Objective: Work with tables, images, and semantic elements

Key HTML Elements:

  • <table><thead><tbody> - Semantic table structure
  • <img alt="..."> - Always include alt text for accessibility
  • title attribute - Tooltip on hover
  • <caption> - Describes table purpose

Interview tip: "Alt attributes are critical for SEO and accessibility. They help screen readers describe images to visually impaired users and improve search results."

Exercise 5: Form Elements & Validation

Objective: Create accessible, validated forms

Key Input Types:

  • <input type="text"> - Plain text
  • <input type="email"> - Email with browser validation
  • <input type="date"> - Date picker
  • <select><option> - Dropdown menu
  • <textarea> - Multi-line text
  • <input type="checkbox"> - Multiple selections
  • <output> - Display computed result

Form Attributes:

  • required - Field is mandatory
  • placeholder - Hint text
  • autofocus - Focus on page load
  • novalidate - Disable browser validation

Interview tip: "Use HTML5 input types for automatic browser validation and better mobile UX. Alt=email triggers keyboard on mobile. Always use labels associated with form fields for accessibility."

Exercise 6: Event Handling

Objective: Implement real-time user interactions

Event Handlers:

  • onblur - When element loses focus (validation)
  • onchange - When value changes
  • onclick - On single click
  • ondblclick - On double click
  • onkeydown/onkeyup - When key is pressed/released
  • onsubmit - When form is submitted

Interview tip: "onblur is best for validation (like phone format check), onchange for dropdown selections, onclick for buttons, and onkeyup for real-time character counting."

Exercises 7-10: Advanced HTML5 Features

Exercise 7: Video & Media

  • <video><source> - Embedded video with multiple formats
  • controls - Show play/pause buttons
  • oncanplay - Fired when video can start playing

Exercise 8: Storage APIs

  • localStorage - Persistent storage (survives browser restart)

  • .setItem(key, value) - Save data
  • .getItem(key) - Retrieve data

Exercise 9: Geolocation API

  • navigator.geolocation.getCurrentPosition() - Get user's coordinates

Exercise 10: Page Unload Events

  • onbeforeunload - Warn user before leaving with unsaved data

CSS3 Exercises

CSS Methods: Inline, Internal, External

1. Inline Styles (Lowest Priority)

<div style="color: red;">

✗ Not reusable, hard to maintain

2. Internal <style> Tags (Medium Priority)

<style>#banner { color: blue; }</style>

✓ Scoped to page, can be reused within page

3. External stylesheet.css (Highest Priority)

<link rel="stylesheet" href="styles.css">

✓ Best practice - reusable across all pages, easy to maintain

Interview tip: "CSS has a cascade. Rules applied later override earlier ones. Inline styles have highest specificity (1000), IDs (100), classes (10), elements (1). External files are best practice for scalability."

Selectors: Universal, Element, Class, ID, Grouping

/* Universal - All elements */
* { margin: 0; padding: 0; }

/* Element selector */
h2 { color: #2c3e50; font-size: 28px; }

/* Class selector (reusable) */
.button { background: #3498db; color: white; }

/* ID selector (unique) */
#mainHeader { font-size: 32px; }

/* Grouping - Apply same styles to multiple */
h3, p, span { font-family: Arial; }

/* Descendant - elements inside another */
div .event-card { border: 1px solid #ddd; }

/* Direct child - immediate children only */
ul > li { list-style: none; }

/* Attribute - elements with specific attributes */
input[type="email"] { border: 2px solid blue; }

/* Pseudo-classes - element states */
a:hover { text-decoration: underline; }
input:focus { outline: 2px solid gold; }
li:nth-child(even) { background: #f0f0f0; }
Colors, Gradients & Backgrounds

Color Formats:

  • HEX: #3498db (most common)
  • RGB: rgb(52, 152, 219)
  • RGBA: rgba(52, 152, 219, 0.8) (with transparency)
  • Named: blue, red

Gradients:

background: linear-gradient(to right, #3498db, #2ecc71); background: radial-gradient(circle, #3498db, #2c3e50);

Background Images:

background-image: url('image.jpg'); background-size: cover;
Box Model: Margin, Padding, Border, Outline

Box Model Components (outside to inside):

  • Margin: Space OUTSIDE the border (transparent)
  • Border: Boundary line around element
  • Padding: Space INSIDE border from content
  • Content: Actual text/image

.card {
  margin: 20px;           /* Space outside */
  border: 2px solid #333; /* Boundary */
  padding: 15px;          /* Space inside */
  outline: 1px dotted gray; /* Additional border (doesn't affect layout) */
}

/* Shorthand: top right bottom left */
margin: 10px 20px 10px 20px;
/* Or: top/bottom left/right */
margin: 10px 20px;
/* Or: all sides */
margin: 10px;

Visibility Difference:

  • display: none - Element not rendered, takes NO space
  • visibility: hidden - Element hidden but still takes space
Flexbox & Responsive Layout

Flexbox for 1D Layout:


.flex-container {
  display: flex;
  justify-content: space-between; /* Horizontal alignment */
  align-items: center;             /* Vertical alignment */
  flex-direction: row;             /* or column */
  gap: 10px;                       /* Space between items */
}

Media Queries for Responsive Design:


/* Default - Mobile first */
.container { width: 100%; padding: 10px; }

/* Tablet (768px and above) */
@media (min-width: 768px) {
  .container { width: 750px; }
  .col { width: 50%; }
}

/* Desktop (1024px and above) */
@media (min-width: 1024px) {
  .container { width: 960px; }
  .col { width: 33.33%; }
}

Interview tip: "Mobile-first approach means starting with mobile styles then adding@media queries for larger screens. This improves performance and ensures accessibility on all devices."

JavaScript Exercises

JS Fundamentals: Variables, Types, Operators

Variable Declaration:

  • const - Constant (cannot change) - USE BY DEFAULT
  • let - Block-scoped variable (can change) - USE FOR LOOPS
  • var - Function-scoped (old, avoid) - DON'T USE

Data Types:


const name = "John";           // String
const age = 25;                // Number
const active = true;           // Boolean
const events = [1, 2, 3];      // Array
const user = {name, age};      // Object
const nothing = null;          // Null
let unknown;                   // Undefined

Operators:

  • + - Addition or string concatenation
  • ++ - Increment by 1
  • == - Loose equality (avoids type checking)
  • === - Strict equality (TYPE SENSITIVE) - ALWAYS USE THIS
  • && - AND logic
  • || - OR logic

Interview tip: "Always use === instead of == to avoid unexpected type coercion. Use const by default for immutability, let for variables that change. Template literals (`${}`) are cleaner than concatenation."

Functions & Arrow Functions

// Traditional function
function greet(name) {
  return `Hello, ${name}!`;
}

// Arrow function (modern, shorter)
const greet2 = (name) => `Hello, ${name}!`;

// With default parameters
const sayHi = (name = "Guest") => console.log(`Hi ${name}`);

// Higher-order: function that takes/returns functions
const applyTwice = (fn, value) => fn(fn(value));

// Callback function
button.addEventListener('click', () => {
  console.log('Button clicked!');
});

Interview tip: "Arrow functions are concise and have implicit return for single statements. They're perfect for callbacks. Traditional functions are needed for: constructors, methods, and when 'this' context matters."

Array Methods: map, filter, forEach

const events = [
  {id: 1, name: 'Workshop', price: 15},
  {id: 2, name: 'Seminar', price: 25},
  {id: 3, name: 'Sports', price: 10}
];

// forEach - Execute function for each item (NO return)
events.forEach(event => console.log(event.name));

// map - Transform each item (RETURNS NEW ARRAY)
const names = events.map(e => e.name);
// Result: ['Workshop', 'Seminar', 'Sports']

// filter - Keep items matching condition (RETURNS NEW ARRAY)
const expensive = events.filter(e => e.price > 12);
// Result: [{id:1,...}, {id:2,...}]

// find - Get FIRST matching item
const workshop = events.find(e => e.name === 'Workshop');

// reduce - Accumulate to single value
const totalPrice = events.reduce((sum, e) => sum + e.price, 0);
// Result: 50

Interview tip: "map transforms data (CRUD 'R' - Read & Project), filter selects (CRUD 'R' - conditions), forEach performs actions (CRUD 'C' or 'U'). forEach doesn't return anything so can't chain. map/filter return arrays - chainable."

DOM Manipulation

// Selecting elements
const element = document.getElementById('name');
const elements = document.querySelectorAll('.event-card');
const first = document.querySelector('#banner');

// Modifying content
element.textContent = 'New text'; // Plain text
element.innerHTML = '<b>Bold</b>'; // With HTML

// Modifying attributes
element.setAttribute('id', 'newId');
element.dataset.eventId = '123'; // data-event-id

// Modifying classes
element.classList.add('active');
element.classList.remove('hidden');
element.classList.toggle('selected');

// Creating elements
const newDiv = document.createElement('div');
newDiv.textContent = 'Event Info';
const parent = document.querySelector('#events');
parent.appendChild(newDiv);

// Event listeners
button.addEventListener('click', (event) => {
  event.preventDefault(); // Stop default action
  console.log('Clicked!');
});

Interview tip: "Use querySelector for flexibility with CSS selectors. textContent is safer than innerHTML. classList is better than className manipulation. Always attach listeners after elements exist in DOM."

Async Programming: Promises & Fetch API

// Fetch with .then().catch()
fetch('https://api.example.com/events')
  .then(response => response.json())
  .then(data => console.log(data))
  .catch(error => console.error('Failed:', error));

// Modern async/await (cleaner)
const getEvents = async () => {
  try {
    const response = await fetch('https://api.example.com/events');
    const data = await response.json();
    console.log(data);
  } catch (error) {
    console.error('Error:', error);
  }
};

// POST data
const registerUser = async (user) => {
  const response = await fetch('/register', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(user)
  });
  return response.json();
};

// Simulate delay
setTimeout(() => console.log('After 2 seconds'), 2000);

Interview tip: "Promises handle async operations. Fetch returns a Promise. async/await is syntactic sugar over promises - cleaner to read. Always handle errors with .catch() or try/catch. Response.ok checks if status is 200-299."

Debugging with Chrome DevTools

Key Tabs:

  • Elements/Inspector: View & modify HTML/CSS live
  • Console: View logs, errors, run JavaScript commands
  • Sources: Set breakpoints, step through code
  • Network: Monitor API calls, file loads
  • Application: View localStorage, sessionStorage, cookies

Common Debugging Steps:

  1. Open DevTools: F12 or Right-click → Inspect
  2. Check Console for errors (red text)
  3. Add console.log() to track variable values
  4. Set breakpoint by clicking line number in Sources tab
  5. Step through code with F10 (next), F11 (into function)
  6. Watch variables to see their values change
  7. Use Inspect Element to modify CSS and see changes live

Interview tip: "DevTools is essential for debugging. Always check the Console first - 90% of issues show as errors there. Use console.log() strategically to trace execution flow. Breakpoints let you pause and inspect state at specific lines."

Quick Reference for Interview

When asked "Explain HTML5":
"HTML5 is semantic markup that improves accessibility and SEO. Key features: DOCTYPE declaration mandatory, semantic tags (<nav>, <section>, <article>), media support (<video>, <audio>), form validation, geolocation API, localStorage for persistence."

When asked "CSS vs CSS3":
"CSS3 is the latest spec with advanced features: media queries for responsive design, flexbox/grid for layouts, gradients, animations, transforms. CSS specificty affects cascade: ID(100) > Class(10) > Element(1). External stylesheets are best practice."

When asked "Explain async JavaScript":
"JavaScript is single-threaded but uses asynchronous patterns for non-blocking operations. Promises represent future values with .then()/.catch(). async/await is syntactic sugar - cleaner. Fetch API handles HTTP requests. Always handle errors and check response.ok."

When asked "Why Bootstrap":
"Bootstrap provides pre-styled components and a responsive grid system, saving development time. Mobile-first approach ensures 12-column responsive grid. Built-in JavaScript plugins (modal, carousel, collapse) for interactivity. Utility classes (m-3, bg-primary) speed up styling."
